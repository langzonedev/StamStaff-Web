# Product Overview

## Purpose

StamStaff is planned as a focused event availability and rostering utility for small teams. It is not intended to become payroll, time tracking, POS, or a general workforce-management suite.

## Planned public prototype journeys

- Manager creates a fictional event and publishes shifts with limited capacity.
- Staff preview shows open, provisionally claimed, full, confirmed, and locked states.
- Staff can demonstrate a provisional claim and release flow.
- Manager preview shows final assignment and roster publication.
- Conflict, offline, delivery-failure, and 48-hour lock states can be inspected.

## Important boundary

A local clickable prototype does not provide real accounts, permissions, shared concurrency, email delivery, or durable cloud data. Those capabilities may only be described as implemented after integration with the approved private authority and end-to-end verification.

## Now / Next / Later

### Now

- Confirm product language and first-slice UX.
- Select architecture and shared contract in the private repository.
- Build a truthful fictional-data PWA prototype after approval.

### Next

- Integrate approved identity, server-authoritative claims, manager assignments, roster lock, and email delivery in staging.
- Pilot with the intended small team and refine accessibility/usability.

### Later

- Cached read-only roster access.
- Push notifications.
- SMS or offline mutations only if evidence and sustainable operations justify them.

## Non-goals

- Payroll, timesheets, clock-in/out, attendance, POS, inventory, or broad HR.
- Real employee/customer data in this public repository.
- Hidden ranking or privileged allocation logic in public code.
